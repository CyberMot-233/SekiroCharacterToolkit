# 使用说明 · 0.10.10

## 启动与存储

- 单文件发行版：只需分发 SekiroCharacterToolkit-0.10.10.exe。首次运行选择工具数据目录，建议放在 E 盘等空间充足的可写位置。
- 这是单 EXE 分发，不是所有工具在内存里运行。Blender、Python、ffmpeg、解析和音频库会释放到所选目录的 app/版本；缓存、日志、配置和默认导出也在该目录。
- 预留至少 4 GB 工具空间，角色、动作与音频另需更多磁盘空间。每次启动校验内置文件；缺失或损坏时从 EXE 恢复。不会从网络下载运行工具。
- EXE 旁生成 .location 小文件记住数据目录，可一起移动，也可删除它后重新选择。按命令行 --choose-dir 可重新选择；--data-dir "E:\工具数据" 可直接指定。
- 开发目录中的原 SekiroCharacterToolkit.exe 仍是多文件版本，不要将它误当作单文件发行版。
- 设置页可独立修改输出、缓存目录。子进程 TEMP/TMP、Blender 配置跟随缓存；不默认写到 C 盘 AppData。操作系统自身的系统日志不属于工具数据。

## 提取角色和武器

1. 「工具链设置」选择自己的已解包只狼目录，应包含 chr、parts、sound、mtd、param。工具不分发游戏资产。
2. 点击「检测工具链」，随后「角色资源 → 扫描角色与武器」。模型与动画来源可分别选择。
3. 「导出任务」勾选 Blender、MP3、装备、清理骨骼、恢复层级、显示 AFF。动作上限 0 表示全部，建议首次用少量动作验证。
4. NPC 可加载并选择外观 PARAM；狼 c0000 可选择左手义手参数。装备挂点和显示状态根据 PARAM/TAE 处理，不是把所有武器固定在手上。
5. 「动作 / 根运动」加载动作，逐项选择或全选。「导出」和「去根运动」独立；选择了动作列表后以勾选为准，不再按数量上限截断。
6. 「武器 / 义手」可单独提取或批量导出。包括子模型、刀鞘、内部骨架和存在的内部动作。
7. 每次提取创建独立任务目录；完成后查看 job_report.json，不以文件存在代替验证通过。

## 输出格式

- package.json：原生提取包索引；维修和 CS2 转换需要保留完整任务目录。
- *.blend：角色、武器、动作、材质与骨架工程。
- textures/png_rgb：无 Alpha 通道的 RGB PNG。原 DDS 和必要透明信息另保留。
- audio/native_events/*.mp3：渲染后的事件音频。原 FEV/FSB 另存，不伪造缺音。
- MP3 是有损格式，事件音频是一次 FMOD 渲染，不等于全部随机变体。

## 根运动、骨架与旧工程维修

- Blender X/Y 为水平，Z 为高度。去根运动将所选轴固定到该动作起始值，不删除根骨，也不清空未选轴和旋转。重复处理会累积；恢复请用备份或重新导出。
- 清理骨骼只移除没有蒙皮、挂点和其他依赖的节点。AFF 可能承担非均匀缩放/剪切，不能整套删除。
- 新导出的「直接生成源骨骼层级」直接写入最终局部动作；旧工程维修按钮才需要重烘。骨骼可以有真实父子关系但不强制 Connected，因为源动作可能有关节平移。
- 「显示 AFF」同时处理骨骼集合可见性、单骨隐藏与选择锁定，不修改权重或动作。
- 旧动作末尾串动作：使用「修复旧工程末帧（从源重建新副本）」。保留动作列表与去根轴，但不继承手工姿态、材质和裁剪修改。
- 删除可见骨关键帧后仍有运动：读取已有工程，使用「裁剪所选动作尾部（含隐藏辅助骨）」，覆盖身体、AFF、根运动、装备和显隐全部通道，先备份。
- 外观修复、骨架修复、音频补跑均需完整提取包；先查看备份和每项报告。

## 报错与取消

导航重复进入 CS2 页的闪退已修复。一般操作异常会显示在窗口底部，并记录到缓存目录的 logs；原始日志比最后一行错误更有诊断价值。

取消提取会结束子进程树，保留部分输出。单文件首次释放可关闭窗口取消；再次运行会校验并补齐。使用同一数据目录时禁止重复启动，避免覆盖正在使用的依赖。

启动器日志：数据目录 launcher-last-run.txt / launcher-error.txt。工具日志：缓存目录 logs。许可证说明见根目录 THIRD_PARTY_NOTICES.md 和 licenses。

## 0.10.3：全量动作内存不足修复

日志中的 Malloc returns null / ArrayMemoryError 表示系统可提交内存不足，不是武器 PARAM 填错。空闲物理内存并不代表还有足够可提交内存；CS2、模拟器等高占用程序会共同消耗额度。工具不自动关闭其他程序，也不修改系统分页文件。

- 导出页「Blender 输出方式」可选择「分批生成多个完整工程」或「全部动作生成一个完整工程」。默认分批，每批 8 个动作；紧张时改为 1–4。每个批次独立启动 Blender，生成时直接完成清理、层级、根运动、AFF 显示，保存一次并只读验证后退出，释放内存。
- 输出在 animation_batches/标识/batch_编号，每批都有角色、武器、材质和该批动作的完整工程。不同批次可能按自身动作保留不同必要辅助骨，不应直接把动作强行拷到另一批骨架。
- blend_batches.json 记录所有所选动作及对应文件。全部所选动作都成功才标为完成；不会悄悄截掉后面的动作。
- 每个成功批次有独立校验点。点击「继续已有提取包（无需重新解包）」选择原任务目录，按相同选项继续，SHA-256 正确的已完成批次跳过。分批模式下选项、输入或算法变化会使用新的批次标识，不套用错误缓存。
- 此继续按钮仅重建 Blender 阶段；音频请点「补跑已有任务音频」，CS2 请到转换页选择原始父级提取包。原始父包仍含全部动作，不需要把多个 blend 合并后才能转换 CS2。
- 已有工程维修（裁剪/骨架/AFF）对某一批操作时，应选择那个 batch_编号 下包含 package.json 的目录。根运动设置也可在初次构建时批量应用。
- 选择「全部动作生成一个完整工程」可输出一个大工程，但全量上千动作仍需要足够系统内存，不能保证低内存电脑可打开它。
- 单批内动作也有帧数预算；极长单个动作仍需要相应内存。提前检测不足会报具体提示并保留完成项，不声称任意内存都能运行。

本次测试：原失败动作和相邻动作共 8 个，保留 73300 义手配置，构建/清理/层级/XY 去根/显示/保存重开/材质检查通过；另完成两个单动作批次测试。未重跑或声称全量 1,434 个动作已验收。
已有多个分批工程想改成单工程：选择「全部动作生成一个完整工程」，点击「继续已有提取包」，选择父级完整 package.json 所在目录。会复用原生采样统一构建一个骨架与全部动作，不直接拼接不同批次的辅助骨架；旧分批结果保留，已有单工程覆盖前备份。


## 0.10.5：直接生成最终 Blender 工程

新导出不再执行「先生成 .blend → 清理后再保存 → 层级重烘后再保存 → 去根后再保存 → AFF 再保存」。

1. 建立网格后、写入动作前计算蒙皮、挂点和父级依赖，直接保留最终需要的骨骼。
2. 每个动作从源 HKX/脸部事件直接计算最终骨架曲线，同步写入武器、显隐、根运动选项。不先创建全量平铺骨骼 Actions，也不生成 hierarchy 的 skin/basis 磁盘缓存。
3. 必要的 AFF helper 按动作发现；后续动作需要增加 helper 时，早先动作只迁移通道并补单位变换，不重新采样烘焙。
4. 每个最终工程仅保存一次。之后用一个只读 Blender 进程重开一次，检查全部动作起中末源 FK、所有根运动样本、材质、骨架依赖及装备事件。验证不会修改或重新保存工程。
5. 分批完整工程、单个完整大工程两种选择都保留。分批是最终交付文件的拆分，不是对同一个文件分阶段加工。

已提取过原生包，无需重新解包游戏：打开新版 → 导出任务 → 选择输出方式 → 「继续已有提取包」。选择包含 package.json 的父目录。新算法不套用旧版检查点；旧导出与备份保留。

结果报告：blender_validation.json 的 method=direct-final、blend_saves=1、intermediate_blends=0；direct_final_validation.json 记录只读检查。装备独立检查见 equipment_saved_validation.json。

测试范围：8 动作完整直接导出；另一个 5 动作单文件工程包含 1,271 帧长动作及武器动作；两个独立单动作批次；辅助骨后插入的旧动作保持测试。对比旧版两个共同动作，32 个采样时刻、5,045,472 个顶点检查最大差异约 0.0841 mm，根变换差异为 0。5 动作工程作者进程约 75.3 秒、峰值工作集约 1.83 GiB，数值仅对应本机此测试，不是任意角色/全量动作的保证。

全量 1,434 个动作未在本次重跑。单文件仍要在内存中容纳最终全部动作；直接导出消除了旧中间工程和全量重复重烘，不能让最终大工程不占内存。内存较少时使用分批模式。


## 0.10.5：本地缓存、逐动作释放、成功自动清理

导出页新增默认开启的两个选项：
- 「动作先写本地缓存并释放内存，全部完成再汇总成品」：每个动作完成并校验后，将最终曲线、插值、句柄和属性写成 NPZ + JSON，释放 Blender Action，再处理下一动作。最后汇总全部动作并只保存一次最终 .blend。不生成分阶段重烘的中间 Blender 文件。
- 「成功并验证后自动删除本次动作 / 临时缓存」：最终成品通过只读重开验证后，删除对应动作缓存；界面任务成功后删除该任务的临时音频、用户缓存与临时文件。失败、取消保留，输入、算法和选项匹配且 SHA256 正确的动作可续跑。损坏的单个动作缓存单独重算。

本机指定缓存根目录：E:\mapper\只狼\SekiroCharacterToolkit\cache。其他电脑仍可在设置页选择自己的非系统盘目录，不硬编码本机路径。
- cache/actions/任务指纹：可恢复的最终动作曲线。
- cache/tasks/任务编号：本次 Python/Blender/音频临时数据；成功后自动清理。
- cache/profile、blender、dotnet 等：主界面与交互式 Blender 的用户目录。
- 日志、配置、成品、其他任务和未知文件不按“清空整个 cache”处理，不自动删除旧版本留下的缓存。
- 自动清理并不删除成品所需的原生包或内部材质缓存，也不删除用户手工文件。

设置页「检测实际缓存路径」会实测 Python tempfile / 用户目录，以及 Blender 临时目录 / 用户配置 / scripts / datafiles。主界面、后台任务、打开模型和 CS2 子工具统一继承本地环境；Blender 自动临时保存关闭，用户主动保存不受影响。

重要区别：磁盘空间不等于 RAM；Windows 分页文件、系统日志及系统/显卡驱动自身写入不受应用的缓存目录控制。本机检查发现自动管理的 C:\pagefile.sys 分配约 13.4 GiB，这不是 cache 目录中的文件。工具不会修改系统分页文件设置。

磁盘动作缓存降低“前面所有动作与当前计算并存”的内存压力，不能让最终大型 .blend 在零内存中保存：汇总阶段仍需加载所有动作。测试中的长动作自身占用较高，峰值不一定低于直接模式。分批完整工程仍是限制最终汇总内存的方式。缓存模式增加磁盘 I/O，不保证比直接模式更快。

本次限定回归：5 动作、含 1,271 帧长动作、74200 装备；14,255 条最终曲线数组精确一致，20 个姿态/网格抽样差异为 0；逐动作 authoring 时最多 1 个 Action、释放后 0 个。未以此声称所有角色或全量 1,434 动作已验证。

# 0.10.10 追加 / 覆盖动画

1. 打开侧栏「追加 / 覆盖动画」，选择 Blender 或 CS2。
2. 「原角色提取包」选择包含 package.json 的目录。Blender 填入已有 .blend；CS2 填入原 addon 和模型名，也可点击「使用当前 CS2 设置」。
3. 点击「加载可追加动作」。列表默认不勾选，区分「已有，选中将覆盖」与「新增」。筛选不会清空其他勾选。
4. 勾选后点击「追加 / 覆盖勾选动画」。只处理勾选动作，不恢复全量任务。已经导出的同名动作（包括该动作中的手工曲线修改）将被覆盖。
5. 处理成功后重新打开目标文件。Blender 的备份在文件旁 backups/append_时间；CS2 的备份在 rawmodels/sekiro/characters/模型名/backups/append_时间，index.json 记录原路径。

覆盖 Blender 动作沿用其已保存的去根运动轴；新动作保留原始根运动。覆盖 CS2 动作保留原 ModelDoc 根运动设置，新动作采用「转换 CS2」页的根运动选项。勾选音频时覆盖动作保留原音量，新动作默认 1 倍，之后可到音量面板调整。关闭音频时保留已有声音事件，新动作不添加声音。

每个分批工程独立更新：指定一个具体 .blend，不会自动修改其他分批文件。目标为本工具生成的层级骨架；旧版平铺骨架需先修复。修改过绑定位置、父级或添加约束的工程不能保证直接追加，检测不兼容时原文件保留。已有动作需要新 AFF 辅助骨时迁移曲线并验证姿态，不删除必要的 AFF。

所选新动作需要原游戏动画包（source_native 或工具设置中的游戏解包目录），音频需要游戏 sound 目录。任务工作文件位于设置的 cache 内，成功后由工具清理本任务缓存，备份和报告保留。最终保存单一大型 .blend 仍需要容纳全部已有动作的内存。
